# YFloat Google CTS adaptive Hook (Native V3 branch)

- **Switch:** YFloat → Screenshot & OCR → Circle engine. Default remains Native Circle V3.
- **Google path:** ActionExecutor → GoogleCtsTrigger → VoiceInteractionManagerService with an explicit YFloat session token.
- **Hook entry:** YFloatModule.onPackageReady installs GoogleV2HookEngine in Google App targets. It does not hook ContextualSearch in system_server.
- **Isolation:** Google V2 interceptors check the active YFloat token/Remote Preferences before acting. Unmarked Home/gesture CTS passes through.
- **Version and one-time matching:** Google 17.60 is the only fixed symbol baseline. When it does not match, the Google process requests the YFloat-hosted cached symbol descriptor keyed by `versionName/versionCode@lastUpdateTime` and the YFloat Google Hook fingerprint. An unchanged APK is rebound from cached class/method/field names and its semantic signature is revalidated inside the new ClassLoader without scanning DEX. When missing/stale/invalid, a Lens-related DEX-only scan runs once per ClassLoader; only successfully installed selection bindings are saved to the YFloat/YSuite host via the UID-validated Google bridge Provider. libxposed Remote Preferences cannot be written from the hooked Google process. Scan failure is memoized only for the current process, allowing recovery on the next process launch. No per-17.64 profile or blacklist exists.
- **Safe failure:** a missing/ambiguous selection signature is never guessed. Google start/remote-lease failures return to Native V3. A CTS session that starts but has no usable selection may still require user cancellation and manual engine switching.
- **Search interception / menu:** Block post-selection dsxb.q(dukp) only for exact 17.60 and targeted contextual/web/Lens search intents for YFloat-owned sessions; do not guess renamed query-result hooks. The Google selection + live text callbacks send authenticated events to GoogleV2UiEngine, which opens the YFloat FloatActionMenu. An installed Hook does not prove callbacks are active; log both cases.
- **More complete failure diagnostics:** Google-side progress reports each phase once even for fast scans. Host diagnostics retain up to 512 characters of the matched/failed signature instead of truncating before the scan totals. The targeted scanner now reports DEX elements examined, Lens-related DEX elements, eligible classes, loadable classes, candidate method shapes, and DEX enumeration errors. It recognizes classes in the same Lens named namespaces when the exact 17.60 anchor class was renamed, but never falls back to unrelated Google DEX categories. A selection subclass may inherit its String/RectF accessors and still pass the same strict structural checks.
- **Scoped scan:** Only DEX partitions containing `FrozenImageView` or `TextSelectionView` are scanned for candidate classes. Other Google App partitions are skipped; there is no APK-wide fallback. If a future build moves obfuscated controllers outside these partitions, matching fails explicitly rather than scanning everything.\n- **Limits:** no device runtime verification is implied by an installed hook or a loaded process; Google may change its data protocol entirely. No guarantee of compatibility for future Google App versions.
- **Google initialization and diagnostics:** After PackageReady, YFloat defers installing Google Hook until Google's Application Context exists (up to 25 × 200 ms), and its cache store reacquires Context for IPC instead of permanently capturing null. The timeout message is based on whether authenticated scan progress arrived; LSPosed's running-target snapshot alone cannot prove the module was or was not injected. Provider rejects due to APK/fingerprint or Google UID now produce explicit host diagnostics. Google app launch failure terminates the manual request immediately.
- **Missing callback recovery:** On a second explicit CTS gesture, release the stale YFloat selection lease and start a new session instead of ignoring the request. Also expire an unresponsive top-level CTS session after the same 120-second lease as Google. Manual scan timeout reports whether LSPosed ever registered a loaded Google target, distinguishing scope configuration from verified injection.
- **Real scan progress:** The LSPosed settings show a progress indicator and persisted stage. Root reload and Google launch are host-tracked. Google process reports 'resolving', anchored Lens DEX partition indexing, checked candidate classes and final registration through UID-checked Provider progress IPC. Only class matching can display a real ratio (processed / eligible candidate classes). Waiting for Hook injection and indexing with unknown totals display indeterminate progress; no fabricated percentage. The 45-second host timeout remains visible with explicit reason. The progress view stops polling when detached.
- **Scan completion and watchdog:** The UID-checked ContentProvider handles `report_hook_scan_v1`; the Lens-related DEX scan uses a 7-second limit, and the host tracks a separate 45-second manual request timeout. A stale manual request expires automatically (including the next time settings is opened) and the LSPosed settings show a persistent last-result summary in addition to the Toast.
- **Manual one-shot switch (LSPosed settings):** The one-time Google Hook rescan toggle is located under YFloat → Advanced permissions → LSPosed, immediately below the Google Circle switch; it is not duplicated in Screenshot/OCR. It arms an APK+fingerprint-scoped force-rescan request, uses Google-only Root hot reload, launches Google, and resets after kick-off while the completion Toast reports the actual match/registration result. Root, LSPosed enablement and Google scope are required.
- **Scan completion Toast:** An actual full scan reports its final state to the authenticated host Provider after the selection Hook registration attempt. The host displays one localized long Toast with installed-hook count and selected method on success or a short failure reason otherwise. The report is deduplicated by APK identity, Hook source fingerprint and result status; cached-profile fast binds never show a second Toast. This reports matched/registered methods, not runtime invocation.
- **Diagnostics:** GOOGLE_HOOK_APK, GOOGLE_CTS_ARM, YFloat-GoogleV2 / selection confidence and source.
- **Validation:** unit tests + debug build; real devices must verify 17.60 and dynamically resolved builds separately for Hook invocation, session ownership, search suppression, YFloat menu, and native CTS isolation.
